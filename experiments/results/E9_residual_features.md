# E9. 보정 모델 입력에 빈자리와 공조기 위치 추가

- 상태: 채택 (2026-11-16). 저장된 보정 모델(`model.pkl` HAC, `model_cac.pkl` CAC)을 다시 학습하고 웹 녹화(HAC 12개, CAC 10개)를 다시 만들었다. 요약은 `docs/34` 6.2.
- 왜: E8에서 랙 제거 + 공조기 두 대 정지 샘플 18개를 더해도 보류 B와 HAC 보류 E가 나빠졌다. 지금 입력은 빈자리에 대해 "같은 줄 2칸 안의 제거 랙 수"와 "같은 냉기 통로의 제거 랙 수"만 알고, 빈자리가 어느 열기 통로에 있는지, 꺼진 공조기와 얼마나 가까운지는 모른다.
- 바꾼 것(`sim/thermal/dct_thermal/residual_model.py`, 입력 17개 → 25개):

  | 새 입력 | 뜻 |
  |---|---|
  | `slots_to_removed` | 같은 줄에서 가장 가까운 빈자리까지 칸 수(없으면 10) |
  | `dist_to_removed_m` | 가장 가까운 빈자리까지 거리, m(없으면 30) |
  | `removed_same_hot` | 이 랙과 같은 열기 통로에 있는 빈자리 수 |
  | `any_removed` | 랙을 뺐는지(0/1) |
  | `dist_to_off_crac_m` | 가장 가까운 꺼진 공조기까지 거리, m(없으면 30) |
  | `dist_to_on_crac_m` | 가장 가까운 켜진 공조기까지 거리, m |
  | `removed_aisle_fan` | 빈자리 뒤 열기 통로들의 공조기 가동 정도 중 가장 낮은 값(빼지 않았으면 1) |
  | `hot_aisle_off_x_removed` | (1 - 이 랙 열기 통로 가동 정도) x 같은 열기 통로 빈자리 수 |

- 학습 데이터: HAC는 그대로 68개, CAC는 68개 + E8의 18개(`residual_model.EXTRA_CAC`). 이유는 아래 "고른 것".
- 시각화 목적이며 공학적 정확성을 주장하지 않는다.

## 1. 입력 조합 비교

## 2. 고른 것과 이유

- 입력은 "둘 다"(8개 모두).
- **HAC는 추가 18개를 넣지 않는다.** 넣으면 하나씩 빼고 본 오차는 더 작지만(0.600 → 0.586) 보류 E가 1.09 → 1.34도로 나빠져, 미리 정한 기준(보류 사례가 고르게 좋아지고 기존 샘플이 나빠지지 않을 때만 바꾼다)을 넘지 못한다. 68개로 학습하면 보류 A, B, D, E가 모두 같거나 좋아진다(B 0.39 → 0.32, D 0.88 → 0.69, E 1.13 → 1.09). 
- **CAC는 추가 18개를 넣는다.** 모든 항목이 좋아진다(B 0.40 → 0.30, D 0.34 → 0.29, E 1.77 → 1.25, 하나씩 빼고 0.320 → 0.267).
- HAC 보류 E가 추가 샘플로 나빠지는 이유: 나빠지는 랙은 빈자리(Rack_05·06) 옆과 맞은편(03, 08, 15, 16)이다. OpenFOAM은 이 랙들이 우리 계산과 거의 같다고(18.6도, 차이 0.1~0.2도) 하는데, 가장 비슷한 학습 샘플(s79, s80: 1줄 앞쪽 랙 제거, 빈자리 뒤 열기 통로의 공조기는 켜짐)에서는 빈자리 옆 랙이 우리 계산보다 2~7도 뜨겁다. 모델은 학습 샘플을 따라가 2~3도를 더한다. E의 OpenFOAM 계산은 수렴했고(2451회) 열 수지도 맞다. **E는 비슷한 학습 샘플과 실제로 다르게 움직이는 사례**이고, 입력을 늘려도 학습에 없는 현상은 배울 수 없다.

## 3. 신뢰 등급 기준 다시 검증

입력이 바뀌면 나무 사이 퍼짐도 바뀌므로 `evaluate_predictor.py`(같은 고장 패턴을 통째로 빼고 학습, 처음 보는 패턴 시험)로 다시 확인했다. 옛 입력은 같은 데이터로 main 코드에서 돌렸다.

| | HAC 68개 옛 → 새 | CAC 86개 옛 → 새 |
|---|---|---|
| 전체 보정 RMSE | 0.84 → 0.82 | 0.84 → 0.87 |
| 90 % 구간 안 | 0.96 → 0.98 | 0.95 → 0.96 |
| `ok` 보정 RMSE(랙 수) | 0.34 (2468) → 0.29 (2413) | 0.57 (3759) → 0.48 (3808) |
| `caution` | 1.11 (1202) → 1.06 (1216) | 1.30 (1238) → 1.44 (1211) |
| `low` | 1.69 (385) → 1.64 (426) | 1.76 (97) → 2.42 (75) |

- 두 장면 모두 등급이 `ok` < `caution` < `low` 순서로 잘 나뉘고 구간 안 비율도 0.96 이상이다. **기준 값(퍼짐 0.45, 1.15)은 그대로 둔다.**
- CAC는 처음 보는 패턴 시험에서 전체 0.03도 나빠졌다. 이 시험은 랙 제거 샘플을 모두 한 패턴으로 묶으므로, 랙 제거 샘플 하나를 시험할 때 랙 제거 샘플 30개를 한꺼번에 빼고 학습한다. 새 입력이 배울 거리가 없는 가장 나쁜 조건이다. `caution`, `low`의 오차가 커진 것도 이 경우다.
- 보류 E의 신뢰 등급(ok/caution/low 랙 수): CAC 옛 68개 12/34/12 → 새 4/42/12(크게 틀릴 수 있는 사례에서 `ok`가 줄었다), HAC 18/38/2 → 18/38/2.

## 4. 바꾼 코드

- `residual_model.py`: 위치 특징 8개, `Geometry.rack_xy`, `crac_xy`, `EXTRA_CAC`.
- `train_predictor.py --cac`(= `--data-dir surrogate_cac` + `EXTRA_CAC`), `--extra 명세 결과폴더`. 학습 이력(`*.meta.json`)에 `n_features`, `extra`를 남긴다.
- `sim/sensors/dct_sensors/solver_l2.py`: 입력 수(`n_features`)나 추가 샘플이 다른 옛 `model.pkl`은 옛 모델로 보고 거부한다(다시 학습 안내). 모델 파일이 없을 때 그 자리에서 학습하는 경우도 CAC는 `EXTRA_CAC`를 더한다.
- `evaluate_predictor.py --data-dir --extra`.
- 다시 학습: `cd experiments/surrogate_model && uv run --python 3.13 python train_predictor.py`, `... train_predictor.py --cac --out model_cac.pkl`.

## 5. 웹 녹화 다시 만들기

`scripts/make_sim_library.py`(HAC), `--variant cac`(CAC)로 녹화 20개(별칭 2개는 정상 녹화를 가리킨다)를 다시 만들고 `build_data.mjs`로 웹 자료로 바꿨다. `check_data.mjs` 모두 통과(모델 출처: HAC `model.pkl` 68개, CAC `model_cac.pkl` 86개).

- 신뢰 등급(랙 x 300초 중 `ok`/`caution`/`low` 수)은 대부분 비슷하다. 가장 크게 바뀐 것은 HAC `cooling_failure`(CRAC_02 정지): `low`가 163 → 2310. 마지막 시점에 `low`인 랙은 줄 끝 랙 7기(01, 10, 11, 20, 31, 41, 51)다. 같은 CRAC_02 정지인 보류 D에서 가장 크게 틀리는 곳도 줄 끝 랙(01, 51, 11)이라, 오차가 큰 곳을 더 조심스럽게 표시하는 쪽으로 바뀌었다.
- `fan_fault`의 설명("보정 모델이 낮은 신뢰 등급을 보이는 랙이 생긴다")은 그대로 맞다(HAC `low` 1300 → 1080).
