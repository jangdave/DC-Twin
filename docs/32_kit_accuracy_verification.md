# 32. Omniverse Kit으로 데이터센터 시뮬레이션 정확도 검증

- 상태: 채택 (2026-11-10). 1단계부터 진행한다.
- 목적: 우리 열 계산(Warp, `hall60_sim`)과 보정 모델(L2)이 **얼마나 맞는지** Kit 안에서 반복해서 확인할 수 있게 한다. 검증은 장면 USD 하나에서 시작하고, 결과도 USD에 다시 적어 Kit 화면(와 나중에 Unreal)에서 볼 수 있게 한다.
- 관련: [31 세 메뉴 역할](31_monitoring_simulation_quickcalc.md)(시뮬레이션은 정확하게), `experiments/results/E5_surrogate_residual_model.md`(보정 모델 검증), `experiments/openfoam_baseline/README.md`(기준 답), `experiments/results/E0_omniverse_capability_probe.md` 2.24(Kit 안 계산), 2.26(Kit 서버 확인)
- 표기: 시각화 목적이다. "정확도"는 **OpenFOAM 대비**이며 실측 대비가 아니다. 공학적 정확성을 주장하지 않는다.

## 1. 사용자 요청과 결정 (2026-11-10)

- 요청: "옴니버스 kit 활용해서 DC 시뮬레이션의 정확도를 검증하는 방향으로 가자"
- 고른 것: **OpenFOAM 기준 비교 자동화**, **물리 점검(자체 검사)**, **우리 모델 개선까지**. 화면 비교(Kit 뷰포트)는 고르지 않았다.
- 만들던 서버 작업 API(`sim/sensors/dct_sensors/jobs.py`)는 **검증 실행기로 같이 쓴다**. 웹 화면 연결은 검증 뒤에 한다(`docs/31` 6장 3~5단계는 뒤로).

## 2. 지금 아는 것 (출발점)

| 항목 | 값 | 출처 |
|---|---|---|
| 우리 솔버 단독, OpenFOAM 대비 | 정상 RMSE 0.65도, CRAC 2대 정지 2.4도(줄 끝 랙 최대 +9도) | `openfoam_baseline/results/comparison*.md` |

| **가장 큰 불확실성** | OpenFOAM 자체의 격자 의존성. 10 cm와 20 cm만 있고 20 cm에서 평균 0.7도, 줄 끝 2.4도 움직인다 | E5 6장 4번 |
| 배우지 않은 조건 | 급기 온도(18도에서만 배움), 고장 직후의 시간 응답 | E5 12장 |

즉 "보정 모델이 OpenFOAM을 0.6도로 흉내 낸다"는 알지만, **OpenFOAM 값이 격자에 따라 얼마나 움직이는지**, **처음 보는 조건(급기 온도, 무작위 조합)에서도 맞는지**, **우리 솔버가 열을 잃거나 만들지 않는지**는 모른다.

## 3. Kit이 맡는 일

Kit에는 공기 흐름 해석 기능이 없다(E0 2.8장). Kit은 **검증의 실행 환경과 결과를 담는 그릇**이다.

| 일 | 방법 |
|---|---|
| 조건 | 조건을 장면 위의 USD 층(`job.usda`, `dct:job:*` 속성)으로 쓴다. Kit이 장면과 층을 합쳐 연다 |
| 우리 계산 | Kit 안 Warp로 `hall60_sim` + 보정 모델(L2). 독립 실행과 같은 값인 것은 2.24장에서 확인했다 |
| 기준 답 | 같은 조건으로 OpenFOAM 사례를 만든다(`gen_case.py`가 같은 장면을 읽는다). 계산은 WSL |
| 결과를 USD로 | 랙마다 우리 값, 보정 값, OpenFOAM 값, 오차를 `dct:verify:*` 속성으로 결과 층(`verify.usda`)에 쓴다. Kit 화면이나 Unreal에서 장면 위에 얹어 랙별 오차를 볼 수 있다 |
| 보고서 | 조건별 RMSE, 최대 오차, 편향, 구간 포함 비율을 표(`report.md`, `report.json`)로 |

## 4. 단계

| # | 내용 | 시간(추정) | 판정 |
|---|---|---|---|
| V1 | **물리 점검(Kit 안)**: ① 열 수지(랙 발열 = CRAC로 나간 열 + 방 안에 쌓인 열, 정상 상태에서 차이 1% 이내) ② 정상 상태 도달(마지막 60초 변화 0.05도 이내) ③ 우리 솔버 격자 수렴(20, 10, 5 cm에서 랙 입구 온도가 수렴하는지). 조건: 정상, CRAC 1대 정지, 같은 통로 2대 정지 | 몇 분(5 cm는 칸 480만 개, GPU) | 숫자로 기록. 기준을 못 넘으면 원인을 찾아 고친다 |
| V2 | **처음 보는 조건으로 검증**: 학습에 없던 무작위 조건 12개(팬, 줄 전력, 고장 조합을 학습 범위 안에서 새 시드로 뽑음)와 급기 온도 4개(16, 20, 22, 24도)를 Kit 실행기로 돌리고 OpenFOAM 기준과 비교. 학습에 넣지 않는다(시험 전용) | OpenFOAM 사례당 약 10~13분 x 16개 = 약 3~4시간(밤에 무인) | 보정 모델 RMSE를 조건 묶음별로. E5의 검증값(0.6도)과 비슷한지 |
| V3 | **OpenFOAM 격자 의존성**: 대표 조건 2개(정상, 같은 통로 2대 정지)를 7.5 cm로 다시 푼다(5 cm는 칸이 8배라 사례당 몇 시간이 걸릴 수 있어 7.5 cm로 시작) | 사례당 30분~1시간(추정) | 10 cm 대비 변화. 크면 "기준 답 자체의 불확실성"으로 보고서에 적는다 |
| V4 | **모델 개선**: V1~V3에서 가장 큰 오차가 나온 곳을 고친다. 후보: 우리 솔버의 지붕 틈 새는 공기 모델(줄 끝 열 쏠림을 작게 보는 원인으로 의심), 급기 온도를 보정 모델 입력에 넣기(V2의 급기 샘플로 학습) | 결과에 따라 | 같은 검증을 다시 돌려 개선 확인. 시험 자료(V2)로 고르지 않는다(과적합 방지) |

**진행 기록**
- V1 1차 완료(2026-11-10, [결과](../experiments/results/V1_physics_check.md)): 10 cm에서 정상은 열 수지 −0.1 %, 격자 수렴(5 cm와 0.02도). **고장 조건은 열 수지 약 3.5 % 어긋나고 격자에 따라 최고 온도가 28~32도로 움직여 수렴하지 않는다.** 지붕 틈 덮어쓰기 가설은 기각. 원인 찾기는 V4로 이어진다.
- V4-1 완료(2026-11-10, [결과](../experiments/results/V4_conservative_advection.md)): 열을 보존하는 이류(`advection="fv"`)로 열 수지 차이가 모든 격자에서 1 % 안쪽이 됐다. **OpenFOAM과의 차이는 거의 그대로**(RMSE 0.7~3.2도)라 큰 오차의 원인은 흐름 모델로 본다. 기본값은 바꾸지 않았다.
- V4-2 완료(2026-11-10, [결과](../experiments/results/V4_openfoam_flow.md)): OpenFOAM 흐름(+난류 확산)을 우리 온도 계산(fv)에 넣으니 **고장 조건 RMSE가 3.17 → 1.18도(CRAC_02 정지), 2.21 → 0.63도(2대 정지)**. 큰 오차의 원인은 흐름 모델로 확인. 정상 조건의 0.7도 차이는 그대로(급기구 모양, 부력 층 등 후보). 정확한 시뮬레이션은 "OpenFOAM이 흐름, 우리 계산이 시간 변화와 센서 값"으로 바꾸는 안을 다음에 검토한다.
- V4-3 완료(2026-11-10, 같은 결과 문서 6장): 정상 조건의 남은 차이는 랙 모델(OpenFOAM은 다공질, 우리는 막힘) 때문. 랙을 같은 가정으로 두면 **우리 온도 계산이 OpenFOAM을 RMSE 0.07~0.73도로 다시 낸다.** 남은 차이는 흐름 모델과 랙 모델이라는 두 가정에서 온다.

V2의 조건 12개는 시험 전용으로 남긴다. V4에서 학습 자료를 늘릴 때는 **새 시드로 따로 뽑은** 조건을 쓴다.

## 5. 결과 파일과 정리

- 실행 결과(사례, 프레임, 큰 파일)는 gitignore된 `sim/out/verify/`와 WSL `~/foam_runs/`. 표와 요약(`report.md`, `report.json`, 랙 입구 CSV)만 `experiments/results/`에 올린다.
- 상용 CFD 도구는 쓰지 않는다(Reality DC 보류). OpenFOAM은 GPL 공개 소프트웨어이며 결과 표를 올리는 것은 문제없다.
- OpenFOAM 계산 중에는 16코어를 거의 다 쓴다. 한 번에 하나만 돌린다.

## 6. 한계

- 기준 답(OpenFOAM)도 모델이다(k-epsilon, 단순 경계, 단열 벽). 실측이 없으므로 "현실과 맞는다"는 말은 하지 않는다.
- V2의 무작위 조건도 같은 대칭 홀, 같은 랙 배치에서 나온다. 다른 배치(랙 이동)는 이번 범위 밖이다.
- 시간 응답(고장 직후)은 OpenFOAM이 정상 상태만 풀어서 검증하지 않는다. 시간 응답을 보려면 OpenFOAM 시간 진행 계산이 필요하고 비용이 훨씬 크다.
