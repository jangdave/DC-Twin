# ADR-011: Unreal과 별도로 가벼운 웹(WebGL) 보기 화면을 추가한다

- 상태: 채택 (2026-11-02, 시제품 확인 통과, 정적 배포 켬)
- 구현: `web/viewer/`, 기능명세 [18](../18_web_viewer_spec.md)
- 날짜: 2026-11-02
- 관련: [ADR-003](ADR-003-delivery-and-ui.md), [ADR-004](ADR-004-streaming-hosting.md), [11 데이터 규격](../11_data_spec.md), [12 Unreal 설계](../12_unreal_design.md)

## 배경
- 지금은 화면이 Unreal 클라이언트 하나뿐이다. 열람자가 직접 체험하려면 Windows 패키지를 받거나 Pixel Streaming(GPU 서버 필요)에 접속해야 한다. 상시 운영할 GPU 서버가 없어서 [ADR-004](ADR-004-streaming-hosting.md)는 "상시 데모 없음, 영상과 패키지로 대체"로 정했다.
- ADR-004는 "WebGL로 **전환**"을 제외했다. 이유는 프로젝트의 UE 클라이언트 증명 목적과 맞지 않기 때문이다. 이번 결정은 전환이 아니라 **추가**다. Unreal은 그대로 주력이고 웹 화면은 가벼운 보조 보기다.
- 게이트웨이가 이미 WebSocket(`/ws`, snapshot과 sample 메시지)을 제공하고, 보정 모델이 붙이는 구간(`lower`, `upper`)과 신뢰 등급(`confidence`)도 같은 메시지에 있다([11 데이터 규격](../11_data_spec.md)). 웹 화면이 받을 데이터는 새로 만들 것이 없다.

## 결정
정적 파일로 배포하는 **보기 전용 웹 화면**을 만든다. 브라우저만 있으면 서버 없이 볼 수 있다.

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 렌더링 | Three.js(WebGL). 버전은 시제품 때 확인하고 적는다 | 소규모 장면에 가볍고 자료가 많다. Babylon.js는 이 규모에 과하다 |
| 모델(갱신 2026-11-03) | 기본은 직접 제작한 랙과 CRAC의 glb(`blender/scripts/export_glb.py`, 텍스처 없음, 재질 색은 직접 정함)이고 "장비 모양" 단추나 `?models=0`으로 상자로 바꾼다. 건물과 홀 배치는 상자 좌표 그대로다. 처음 결정은 다음과 같다: 장면 USD에서 뽑은 상자 좌표(`layout.json`)를 `scene.json`(8 KB)으로 줄여 그린다: 랙 60기, CRAC 8기, 통풍구, 격벽. 외관 건물과 텍스처는 제외. glb 변환은 이후 과제 | 건물 USD가 18 MB라서 그대로는 무겁다. 상자 좌표만으로 정보를 보이는 데 충분했고 용량이 거의 없다 |
| 표시 | 랙별 입구 온도 색, 알람 강조, 선택한 랙의 90% 구간과 신뢰 등급 막대 | UE와 같은 색 규칙(`ok`, `caution`, `low`, `fallback`)을 써서 같은 정보를 보이게 한다 |
| 데이터(정적 배포) | 녹화 파일(JSONL, 예: 팬 고장 L2 녹화)을 브라우저에서 재생 | 서버 없이 GitHub Pages로 올릴 수 있다 |
| 데이터(로컬) | 같은 화면이 게이트웨이 `/ws`에 붙는 "라이브 모드" | 데이터 경로(생성기 → 게이트웨이 → 화면)를 웹에서도 증명한다 |
| 범위 밖 | 현실적인 외관(단순 상자 건물 외관은 [20](../20_platform_flow_spec.md)에서 추가), 둘러보기 연출, 열 볼륨, 랙 이동 편집, 나이아가라와 음향 | Unreal에서만 만들기 쉬운 기능이고, 이 화면의 목적(상시 체험)과 거리가 멀다 |

화면 코드는 `web/viewer/`에 둔다. 게이트웨이나 생성기의 메시지 형식은 바꾸지 않는다.

## 근거
- 상시 체험 수단이 없다는 ADR-004의 가장 큰 한계를 비용 없이 줄인다. 링크 하나로 온도 색과 신뢰 막대를 볼 수 있다.
- 데이터가 "시뮬레이션 → 센서 생성기 → 게이트웨이 → 화면"으로 흐르는 구조는 화면 엔진과 무관하다. 클라이언트를 두 개 연결해 보면 이 구조가 화면에 묶이지 않았다는 증거가 된다.
- 목표 직군(UE 클라이언트)을 중심으로 두면서 웹 연동 역량도 함께 보인다(ADR-003의 "일부는 웹" 방향과 같다).

## 대안
- **Pixel Streaming만 유지**: 상시 데모가 계속 없다. 비용을 쓰지 않는 한 해결되지 않는다.
- **Unreal 화면을 WebGL로 전환**: UE 클라이언트 증명 목적과 맞지 않아 ADR-004에서 제외했다.
- **Unreal Pixel Streaming을 상시 클라우드 GPU로 운영**: 비용과 관리 부담이 크고 접속 빈도가 낮아 효용이 작다.
- **Babylon.js 등 다른 엔진**: 기능은 충분하지만 이 규모에서는 Three.js와 큰 차이가 없고 자료가 적다. 시제품에서 막히면 다시 검토한다.
- **영상만 제공**: 가장 쉽지만 열람자가 데이터를 직접 바꿔 볼 수 없다.

## 한계
- 화면 품질은 UE에 크게 못 미친다. 이 화면은 "정보를 보는 용도"이고 외관과 연출은 UE 영상으로 보인다.
- glTF 변환과 용량 줄이기가 가장 큰 불확실성이다. 변환 경로(Blender 5.1 가져오기와 내보내기, 또는 USD 도구)는 시제품에서 확인한다.
- 정적 배포는 녹화 재생이라서 "실시간"이 아니다. 라이브 모드는 로컬 게이트웨이가 있을 때만 된다. 문서와 화면에 이 차이를 표시한다.
- 시뮬레이션 값은 시각화 목적이며 공학적 정확성을 주장하지 않는다(`docs/04_clean_room_policy.md`). 이 화면에서도 같은 문구를 보인다.
- 공개 배포 전에 회사 자산 분리 규칙(금지어 점검)을 통과해야 한다. 데이터는 이 저장소의 가상 시설 결과만 쓴다.

## 최소 시제품 시험 결과 (2026-11-02)
- [x] 모델 용량: glb 대신 상자 좌표 8 KB. 첫 로딩 전체가 gzip 약 282 KB(기준 1.5 MB). 첫 화면까지의 시간은 소프트웨어 그래픽 헤드리스 환경이라 재지 않았다(사용자 PC 확인 필요)
- [x] 녹화(JSONL)를 재생하면서 랙 색이 UE와 같은 색 곡선(18~35도)으로 바뀐다(색 값은 자동 시험에서 UE 코드와 같은 표로 확인)
- [x] 랙을 누르면 90% 구간과 신뢰 등급 막대가 나온다. 팬 이상 마지막 시각의 등급이 ok 48, low 12로 UE 실제 연결 확인과 같다
- [x] 같은 화면이 게이트웨이 `/ws`에 붙어 라이브로 갱신된다(센서 204개 수신, 버린 메시지 0건, 끊김과 재접속, 원격 `ws://` 거부)
- [x] GitHub Pages 배포: 2026-11-02 사용자 승인으로 켰다(`.github/workflows/web-viewer-pages.yml`, main 병합 때 자동 배포). 주소 https://jangdave.github.io/Portfolio_DT/ . 배포 전 저장소와 빌드 결과(dist)의 금지어 점검은 0건이다. 이 화면에는 회사 프로젝트의 코드, 에셋, 데이터가 없다

자세한 측정과 한계는 [기능명세 18 10장](../18_web_viewer_spec.md)에 있다.
