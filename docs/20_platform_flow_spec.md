# 20. 외관 → 홀 → 시뮬레이션 흐름 명세 (웹·Unreal 공통)

- 상태: 초안 (2026-11-02). 웹 쪽(4장)은 구현·확인 완료, Unreal 쪽(5장)은 구현 전
- 목적: 첫 화면은 건물 외관, 건물을 누르면 내부(홀)로 들어가 센서와 시뮬레이션을 확인하는 "플랫폼 형태"를 웹 보기 화면과 Unreal 클라이언트가 **같은 규칙**으로 구현하도록 정한다.
- 관련: [ADR-008](decisions/ADR-008-screen-flow-exterior-to-floor.md)(흐름의 큰 틀), [ADR-011](decisions/ADR-011-webgl-viewer.md), [12 Unreal 설계](12_unreal_design.md), [18 웹 보기 화면 명세](18_web_viewer_spec.md), [11 데이터 규격](11_data_spec.md)
- 참고 방식: 설계 생각만 참고하고 말로 새로 정리했다. 코드와 에셋은 가져오지 않았고, 이 문서에 외부 프로젝트 이름은 적지 않는다([04 회사 자산 분리 규칙](04_clean_room_policy.md)).

## 1. 무엇을 바꾸나
ADR-008은 흐름(외관 → 층 → 둘러보기)을 정했지만, 현재 웹 보기 화면에는 외관이 없고(홀만 표시), 두 클라이언트가 같은 "화면 전환 규칙"을 갖고 있지 않다. 이 문서는 다음 세 가지를 정한다.
1. 화면 단계와 전환 조건
2. 단계를 바꾸는 **화면 이동 명령**의 이름과 번호(웹·Unreal 공통)
3. 클라이언트별 구현 범위와 확인 기준

## 2. 화면 단계

| 번호 | 단계 | 보이는 것 | 카메라 | 들어가는 조건 |
|---|---|---|---|---|
| S1 | 외관 | 건물 겉모습, 건물 전체 요약(전력, 효율, 알람 수) | 건물을 도는 궤도 카메라 | 처음 열 때 |
| S2 | 홀 | 랙 60기 색, CRAC, 알람 목록, 선택한 랙의 구간·신뢰 막대 | 홀 안을 내려다보는 궤도 카메라(웹은 지금 화면과 같다) | S1에서 건물 선택 |
| S3 | 시뮬레이션 보기 | S2 + 시나리오 선택, 재생 막대, 전력 보기, (Unreal만) 열 볼륨 | S2와 같다 | S2에서 시나리오 선택 또는 보기 전환 |
| S4 | 둘러보기 | 걸어 다니는 시점 | 1인칭 | **Unreal만** 구현. 웹은 범위 밖 |

- 뒤로 가기: S3 → S2 → S1 순서로 거꾸로. 키보드 `Esc`와 화면의 "뒤로" 단추 모두 지원.
- 처음 열 때 항상 S1. 단, 주소 매개변수로 단계를 직접 지정하면 건너뛴다(웹).
- 외관 단계에서도 센서 데이터가 들어오면 건물 요약(알람 수 등)은 갱신한다. 값이 없으면 "데이터 없음"으로 표시한다.
- 시뮬레이션 값은 시각화 목적이며 공학적 정확성을 주장하지 않는다는 문구를 S2·S3에서 계속 보인다.

## 3. 화면 이동 명령

화면 이동은 "명령" 하나로 표현한다. 웹 안의 화면 조각들과 Unreal의 서브시스템이 같은 이름을 쓴다. 이름은 한 번 정하면 바꾸지 않는다(새로 추가만).

| 번호 | 이름 | 값 | 동작 |
|---|---|---|---|
| 10001 | `view.goto` | `exterior` \| `hall` \| `walk` | 해당 단계로 이동 |
| 10002 | `view.back` | 없음 | 한 단계 뒤로 |
| 10003 | `view.select` | `rack_01` 같은 장비 ID, 또는 비움 | 장비 선택(비우면 해제) |
| 10004 | `view.layer` | `temp` \| `power` | 표시 층 전환 |
| 10005 | `sim.scenario` | 시나리오 이름 | 시나리오 선택(웹은 녹화, Unreal은 게이트웨이 재생 입력) |

- 번호는 `docs/11` 데이터 규격 표에 같이 적어 두고, 시험이 표와 구현이 같은지 확인한다.
- **준비 전 명령은 쌓았다가 보낸다.** 3D 장면이 아직 로딩 중일 때 받은 명령은 목록에 쌓고, 준비가 끝나면 순서대로 실행한다. 같은 이름의 명령이 여러 개 쌓였으면 마지막 것만 실행한다(건너뛰어도 되는 이동 중복 제거).
- 알 수 없는 이름이나 값은 무시하고 오류 횟수만 센다(웹: 화면 조각 안내에 표시. Unreal: 로그).
- 명령은 센서 데이터 메시지(`snapshot`, `sample`, `alarm`)와 **섞지 않는다**. 센서 쪽 형식은 바꾸지 않는다.

## 4. 웹 보기 화면 구현 범위

### 4.1 기능 요구사항 (기존 FR-01~73에 이어 FR-80번대)
| 번호 | 요구 |
|---|---|
| FR-80 | 처음 열면 S1 외관을 보인다. 건물은 단순 상자 모양(홀 바깥 치수에서 만든 껍질 + 지붕)이고 장비 상자와 같은 방식으로 `scene.json`에서 그린다 |
| FR-81 | 건물을 누르거나 `Enter`를 누르면 S2로 이동한다. 이동은 카메라가 건물 안으로 들어가는 0.8초 전환이고, "동작 줄이기" 설정이면 즉시 바꾼다 |
| FR-82 | S1에서 건물 요약 카드를 보인다: 알람 수, 가장 높은 입구 온도, 전력 집계(`aggregate`가 있을 때). 값이 없으면 "데이터 없음" |
| FR-83 | `view.back` 단추와 `Esc`로 거꾸로 이동한다 |
| FR-84 | 주소 매개변수 `stage=exterior\|hall`을 지원한다. 기존 `view=power` 같은 표시 층 매개변수는 그대로 쓴다 |
| FR-85 | 화면 이동 명령 큐: 장면이 준비되기 전 명령을 쌓았다가 실행한다 |
| FR-86 | 단계가 바뀌어도 센서 저장소와 재생 위치(`t`)는 유지한다 |

### 4.2 모델
- 외관 건물은 새 에셋 없이 `layout.json`의 홀 치수에서 계산한 상자와 지붕으로 만든다. 실제 시설 형상은 쓰지 않는다. 건물 USD(18 MB)나 glb 변환은 이후 과제(`docs/18` 11장)이고 이 명세의 선행 조건이 아니다.
- 용량 기준: 첫 로딩 gzip 합계 1.5 MB 이하를 유지한다(`docs/18` 6장).

### 4.3 시험
- 자동 시험: 단계 전환 상태기계(허용·거부 전환, 뒤로 가기), 명령 큐(준비 전 쌓기, 같은 이름 중복 제거, 모르는 명령 무시), 주소 매개변수 읽기.
- 화면 확인(`tools/ui_check.mjs` 확장): 처음 S1 → 건물 클릭 → S2 → `Esc` → S1, 좁은 화면, 동작 줄이기.

## 5. Unreal 클라이언트 구현 범위

| 번호 | 요구 |
|---|---|
| UR-01 | 화면 단계를 관리하는 한 곳(서브시스템, 예 `UDCTViewFlowSubsystem`)을 둔다. 단계와 전환 규칙은 3장 표와 같다 |
| UR-02 | 외관 단계는 ADR-008의 "최소 외관"(단순 건물, 기본 하늘과 땅)부터. 현실적 환경은 핵심이 동작한 뒤 |
| UR-03 | 건물 클릭으로 홀 서브레벨을 불러오고 카메라를 옮긴다. 뒤로 가기로 서브레벨을 내린다 |
| UR-04 | 3장 명령을 받아 같은 이름으로 처리한다. 웹과 같은 명령 큐 규칙(준비 전 쌓기)을 쓴다 |
| UR-05 | 센서 저장소(`UDCTSensorSubsystem` 등 기존 것)는 단계가 바뀌어도 초기화하지 않는다 |
| UR-06 | 단계 이동 중 게이트웨이 연결이 끊기거나 시나리오가 다시 시작해도 센서 값과 알람이 어긋나지 않는다(`docs/19` H1, H2 수정이 선행) |

- 선행 조건: `docs/19`의 Unreal 고장 항목(H1 시나리오 시작 시 값 비우기, H2 끊김 때 색 되돌리기)을 먼저 고친다. 이 흐름은 단계가 바뀔 때 상태가 섞이는 문제를 더 자주 드러내기 때문이다.
- Unreal 쪽 구체 클래스 이름과 레벨 구성은 구현 때 `docs/12`에 적는다.

## 6. 확인 기준 (두 클라이언트 공통)
1. 처음 열면 외관이 나온다.
2. 건물을 누르면 홀로 들어가고, 뒤로 가면 외관으로 돌아온다.
3. 홀에서 시나리오를 바꿔도 단계가 바뀌지 않는다. 단계를 바꿔도 시나리오와 재생 위치가 유지된다.
4. 로딩 중에 보낸 명령(주소 매개변수 또는 외부 명령)이 로딩이 끝난 뒤 한 번만 실행된다.
5. 알 수 없는 명령이 오류 없이 무시되고 횟수만 센다.
6. 같은 시나리오·같은 시각에서 두 클라이언트가 보이는 알람 수와 신뢰 등급 수가 같다(팬 이상 마지막 시각: ok 48, low 12).

## 7. 결정과 이유
| 결정 | 이유 | 다른 방법 |
|---|---|---|
| 화면 이동을 명령으로 표현하고 번호를 고정 | 두 클라이언트와 시험이 같은 표를 보고 움직인다. 나중에 외부 화면(웹 패널 등)이 Unreal을 조종할 때도 그대로 쓴다 | 클라이언트별로 따로 정의: 어긋나기 쉽다 |
| 웹 외관은 상자 건물 | 용량 거의 0, 에셋 라이선스 없음 | 건물 glb: 용량과 변환 불확실성이 크다 |
| 명령을 센서 메시지와 분리 | 게이트웨이와 생성기 형식을 건드리지 않는다 | 센서 메시지에 섞기: 형식 변경과 시험 비용 |
| 둘러보기는 Unreal만 | 웹의 목적(가벼운 상시 체험)과 거리가 멀다 | 웹 1인칭: 충돌 처리와 조작 비용이 크다 |

## 8. 진행 순서
1. (이 문서) 명세 확정 → `docs/11`에 명령 번호표 추가
2. 웹: 단계 상태기계와 명령 큐(순수 로직, 자동 시험) → 외관 장면과 전환 → 화면 확인 도구
3. Unreal: `docs/19` H1·H2 수정 → 서브시스템과 최소 외관 → 서브레벨 전환
4. 두 클라이언트 비교 확인(6장 6번)

## 8.1 웹 구현 결과 (2026-11-02)
- 구현: `web/viewer/src/flow.js`(단계, 명령 검사, 명령 큐, 건물 요약), `scene.js`(외관 건물, 단계 전환, 건물 위 경고등), `main.js`, `ui.js`. 요구 FR-80~86 모두 구현.
- 시험: `test/flow.test.js` 12개(전체 74개), `tools/ui_check.mjs`의 외관 → 홀 → 외관 항목(전체 33개 통과). 화면은 헤드리스 소프트웨어 그래픽으로 확인했고 실제 GPU 확인은 사용자 PC가 필요하다.
- 정한 것: 외관 건물 위 경고등은 가장 심한 알람 색(랙과 CRAC 기준). 화면 이동 명령은 `window.__viewer.dispatch({name, value})`로 넣을 수 있다.
- 달라진 점: 기존 주소는 이제 외관에서 시작한다. 홀에서 바로 열려면 `?stage=hall`을 붙인다. 점검 도구는 모두 `stage=hall`을 쓰도록 고쳤다.
- 명령 번호표는 이 문서와 `src/flow.js`에 있다(두 곳이 같은지는 `flow.test.js`가 확인). `docs/11`로의 이전은 Unreal 구현 때 정한다.

## 9. 열린 문제
- 건물 외관 모양(층수, 지붕)은 가상 시설 기준으로 정한다. 정하기 전까지 웹은 홀 크기에서 계산한 단순 상자를 쓴다.
- 명령 번호표를 `docs/11`로 옮길지, 이 문서에 둘지는 구현 때 한 곳으로 정한다(중복 금지).
- 외부 화면이 Unreal을 조종하는 경로(Pixel Streaming 메시지 연결)는 이 명세 밖이다. 필요해지면 ADR을 새로 쓴다.
