# 23. 웹 도심 배경과 화질 단계

- 상태: 채택 (2026-11-03)
- 목적: 외관 주변에 도시 블록을 두어 "도심 한복판의 데이터센터"처럼 보이게 하고, 모바일과 저사양 노트북에서도 돌도록 화질 단계를 둔다.
- 관련: [22 외관 환경과 공기 흐름](22_web_exterior_airflow_spec.md), [18 웹 보기](18_web_viewer_spec.md)
- 표기: 가상의 도시다. 실제 지역이나 건물을 본뜨지 않았다. 외부 에셋 없이 코드로 만들었다.

## 1. 도심 (`web/viewer/src/city.js`)

| 요소 | 방법 |
|---|---|
| 블록 | 가운데 블록(데이터센터 부지)을 빼고 7×7(낮은 화질은 5×5) 격자. 간격 210×185 m, 도로 폭 20 m |
| 건물 | 블록마다 2×2 필지(12%는 빈 터). 높이는 거리에 따라: 가까운 블록 10~26 m(데이터센터가 가려지지 않게), 중간 26~62 m, 먼 곳 45~150 m. 전부 한 덩어리로 합쳐 그린다 |
| 창 | 캔버스로 그린 창 무늬를 건물 크기에 맞게 반복. 저녁에는 켜진 창이 발광(`?sky=dusk`) |
| 도로 | 노란 점선과 가장자리 선이 있는 아스팔트 띠 |
| 가로수, 차량 | 인스턴스로 그림. 차량은 도로를 따라 움직임 |
| 반사 | 하늘에서 반사 지도를 만들어 유리와 금속에 비춤(높은 화질만) |
| 그림자 | 해 그림자 지도는 정지 상태에서 한 번만 그리고 바뀔 때만 다시 그림 |

외관 기본 카메라는 도시 위로 올렸다(높이 약 85 m). 가까운 블록 건물이 데이터센터를 가리지 않는다.

## 2. 화질 단계 (`web/viewer/src/quality.js`)

| 항목 | 낮음 | 보통 | 높음 |
|---|---|---|---|
| 화면 배율 상한 | 1 | 1.5 | 2 |
| 그리는 화소 수 상한 | 1280x720 | **FHD(1920x1080, 일반 기준)** | 2560x1440 |
| 후처리 빛 번짐 | 없음 | 약하게(절반 해상도) | 조금 세게 |
| 후처리 접촉 그림자(SSAO) | 없음 | 없음 | 있음 |
| 그림자 지도 | 없음 | 2048 | 4096 |
| 공기 흐름 입자 | 2,500 | 5,000 | 7,000 |
| 도시 블록 | 5×5 | 7×7 | 7×7 |
| 차량 | 0 | 60 | 120 |
| 가로수 | 200 | 600 | 1,200 |
| 반사 | 없음 | 없음 | 있음 |
| 홀의 랙 모델(삼각형 약 27만) | 눌러서 받음 | 자동 | 자동 |

- 자동 선택: 터치 화면이거나 폭 700px 미만(휴대폰, 태블릿)이면 **보통**(2026-11-11 변경, 이전은 낮음). 그중 메모리 2 GB 이하나 코어 2개 이하만 낮음. PC는 메모리 4 GB 이하나 코어 4개 이하면 낮음, 메모리 8 GB 이상이고 코어 8개 이상(모르면 포함)이면 높음, 나머지는 보통. 실제 프레임이 22fps 아래면 한 단계 낮춘다.
- **그리는 해상도**: 기기 배율, 단계의 배율 상한, 화소 수 상한(`maxPixels`) 중 가장 작은 값을 쓴다(0.5 아래로는 내리지 않음). 보통 단계에서 FHD 화면은 그대로, QHD나 4K 화면은 FHD 화소 수에 맞춰 낮춰 그린다(`pixelRatioFor`). 일반 기준을 FHD로 둔 것은 사용자 결정(2026-11-05)이다.
- **후처리**(`src/fx.js`): 빛 번짐은 문턱 0.95라 표시등, 켜진 창, 알람 색처럼 밝은 것만 번진다. 단계가 켜지만 `?fx=off`로 끌 수 있고 `?fx=on`으로 강제로 켠다. 자동 시험 브라우저는 소프트웨어 렌더링이라 기본으로 끈다. 켜면 하늘 색이 톤 매핑을 거쳐 조금 덜 짙어진다(꺼진 화면과 색이 다름).
- 직접 고르기: 주소에 `?q=low|mid|high`, 또는 도움말의 "화질" 선택(바꾸면 다시 불러옴).
- 자동 낮춤: 처음 2.5초 뒤 3초 동안 평균 프레임이 22 미만이면 한 단계 낮춘다(그림자, 입자, 차량, 가로수, 해상도, 반사). 도시 블록 수는 다시 만들지 않으므로 그대로다. `?q=`를 직접 준 경우와 자동 시험 브라우저에서는 하지 않는다.
- 자동 시험 브라우저는 보통으로 고정한다(소프트웨어 렌더링이라 결과가 흔들리지 않게).

## 3. 측정 (2026-11-03)

소프트웨어 렌더링(SwiftShader)이라 실제 GPU보다 **훨씬 낮은 값**이다. 단계끼리 비교하는 용도이며 실제 기기 프레임을 보장하지 않는다.

| 장면 (모바일 폭 390 px, 배율 3) | 프레임 | 그리기 호출 | 삼각형 | 메모리(힙) |
|---|---|---|---|---|
| 외관, 높음 | 5 | 27 | 22만 | 58 MB |
| 외관, 보통 | 14 | 27 | 19만 | 55 MB |
| 외관, 낮음 | 22 | 26 | 17만 | 46 MB |
| 홀, 낮음(랙은 상자) | 60 | 14 | 5천 | 26 MB |
| 홀, 높음(랙 모델 사용) | 13 | 32 | 30만 | 55 MB |

- 높음 단계에서 가장 비싼 것은 도시(건물 창 무늬와 가로수), 반사, 그림자 순이었다(끄면 4 → 20 프레임).
- 용량: 첫 로딩 약 511 KB(gzip), 모델과 속도장까지 약 1.5 MB. 도시는 코드로 만들어 용량이 거의 늘지 않는다.

## 4. 확인하지 못한 것

- **실제 모바일과 저사양 노트북의 프레임**: 이 환경에 없다. 사용자 PC나 기기에서 `?q=` 단계별로 확인해야 한다.
- 메모리 한도가 낮은 기기에서의 메모리 부족 여부.
- 터치 조작(두 손가락 확대)의 사용감.

## 6. 2026-11-06 갱신 (이후 추가된 것)

- **외벽 9종**: 유리, 띠창, 콘크리트, 벽돌, 금속에 창이 적은 구멍창, 세로 틈창, 큰 창, 창고형 벽을 더했다. 종류마다 2가지 변형이다. 창이 적은 4종이 건물의 3할 넘게 섞인다(`city.test.js`가 확인). 비율은 `city.js`의 `FACADE_BY_KIND`에서 고친다.
- **저녁 창 불빛**: 건물마다 창의 40 %만 켠다. 켜질 창은 황금비 격자(R2 수열)로 골라 한곳에 뭉치지 않고 건물 구역(약 60 m)마다 시작점이 다르다. 데이터센터 유리창도 같은 규칙이다.
- **먼 도로**: 도시 도로를 바닥 원판 가장자리(약 1090 m)까지 이어 끝이 끊겨 보이지 않게 했다.
- **부지 조명**: 가로등 12개의 빛 웅덩이와 건물 둘레 벽등(9 m 간격)이 저녁에만 켜진다.
- **조작**: 왼쪽 버튼으로 돌리고(끌지 않고 누르면 선택), 휠로 확대·축소한다. 화면 이동(pan)은 없고 확대·축소에는 한계가 있다(건물 안쪽, 도시 밖은 못 본다).
- 확인은 모두 소프트웨어 렌더링과 자동 시험이다. 실제 GPU와 휴대폰은 확인하지 못했다.
