# 18. 웹 보기 화면 기능명세

- 상태: 초안 v1 (2026-11-02). 구현하면서 수치와 화면 구성이 바뀔 수 있고, 바뀌면 이 문서를 같이 고친다.
- 목적: Unreal 클라이언트와 별도로 만드는 **웹(WebGL) 보기 화면**의 기능, 데이터, 화면, 성능 기준, 시험 방법을 정한다. 이 문서만 보고 구현과 인수 시험을 할 수 있어야 한다.
- 관련 문서: [ADR-011](decisions/ADR-011-webgl-viewer.md)(왜 만드는가), [11 데이터 규격](11_data_spec.md), [12 Unreal 설계](12_unreal_design.md)(같은 색 규칙을 쓴다), [09 USD 규격](09_usd_spec.md)

## 1. 목표와 범위

### 1.1 목표
1. 열람자가 **설치 없이 브라우저 링크 하나**로 가상 데이터센터의 랙 온도, 알람, 보정 모델의 90% 구간과 신뢰 등급을 본다.
2. 같은 화면이 **녹화 재생**(서버 없음)과 **게이트웨이 라이브**(`/ws`) 두 방식의 데이터를 받는다. 화면 코드는 하나다.
3. Unreal 클라이언트와 **같은 색 규칙과 같은 알람 표시**를 써서, 두 화면이 같은 값을 같게 보여 준다.

### 1.2 범위 밖 (하지 않는 것)
- 외관 건물, 둘러보기 연출, 열 볼륨(VDB), 나이아가라, 공간 음향: Unreal에서만 한다.
- 장비 제어, 로그인과 권한, 랙 이동 편집(읽기 전용).
- 모바일 전용 화면(작은 화면에서 깨지지 않는 정도만 맞춘다), XR.
- 공학적 정확성의 주장. 이 화면의 값은 시각화 목적이다(`04_clean_room_policy.md`).

### 1.3 사용자와 상황
| 사용자 | 상황 | 이 화면이 해야 하는 일 |
|---|---|---|
| 포트폴리오 열람자 | 링크를 열어 1~2분 훑어본다 | 열자마자 움직이는 화면이 나온다. 설명 없이 "무엇을 보는지" 알 수 있다 |
| 면접관 | 시나리오를 바꿔 가며 질문한다 | 시나리오 전환, 재생 위치 이동, 랙 선택이 빠르게 된다 |
| 개발자(본인) | 로컬에서 게이트웨이와 맞춰 본다 | 주소만 바꾸면 라이브로 붙고, 연결 상태와 오류가 화면에 보인다 |

## 2. 용어
| 말 | 뜻 |
|---|---|
| 녹화 | 센서 생성기가 만든 `.jsonl`을 화면용으로 줄인 파일(4장) |
| 재생 시각 | 녹화 안에서 지금 보여 주는 시점(초). 0~300 |
| 라이브 | 게이트웨이 `/ws`에서 받는 실시간 흐름 |
| 등급 | 보정 모델의 신뢰 등급 `ok`, `caution`, `low`, `fallback`([11](11_data_spec.md), [E5](../experiments/results/E5_surrogate_residual_model.md)) |
| 구간 | 보정값의 90% 구간(`lower`, `upper`) |

## 3. 화면 구성

```

│ 상단 표시줄: [제목] [● 녹화 재생 / ● 라이브] [시나리오 ▼] IT 전력 | 냉각 | PUE │
├───────────────────────────────────────────────────┬──────────────────────────┤
│                                                   │ 보기 값: (●온도 ○배기 ○전력) │
│                3D 장면 (Three.js)                  │ ──────────────────────── │
│    랙 60기 색칠, CRAC 8기, 격벽, 통풍구           │ 선택한 장비 상세            │
│    랙 위 신뢰 막대, 알람 테두리                    │  · 값, 단위, 알람 상태     │
│                                                   │  · 90% 구간, 등급, 막대    │
│                                                   │  · 최근 2분 추이 그래프    │
│   [위에서] [비스듬히] [처음 위치]                  │ ──────────────────────── │
│                                                   │ 알람 목록(최근 순)         │
├───────────────────────────────────────────────────┴──────────────────────────┤
│ 하단: [▶/⏸] [속도 1x 2x 5x 10x] [──●──────── 시간 막대 ────] 03:12/05:00 [반복] │
│ 범례: 온도 색 곡선 18~35도 | 신뢰 등급 색 | 알람 테두리                         │
│ 안내: 시뮬레이션 값은 시각화 목적이며 공학적 정확성을 주장하지 않는다           │
└──────────────────────────────────────────────────────────────────────────────┘
```
- 폭 900px 미만에서는 오른쪽 패널이 하단으로 내려가고(탭), 3D 장면이 위에 남는다.
- 어두운 배경, 상태 색은 [12](12_unreal_design.md) 6장의 방침을 따른다.

## 4. 데이터

### 4.1 입력 두 가지와 공통 내부 형식
두 입력 모두 화면 안에서 같은 **센서 값 저장소**(5.2)를 갱신한다. 화면은 입력이 녹화인지 라이브인지 모른다.

| 입력 | 주소 | 비고 |
|---|---|---|
| 녹화 재생 | `data/rec/<시나리오>.json` (정적 파일) | 기본 모드 |
| 라이브 | `ws://<호스트>/ws` (주소 창 `?live=ws://127.0.0.1:8080/ws`) | 게이트웨이 메시지 그대로([11](11_data_spec.md) 4.3) |

### 4.2 정적 자료 (빌드할 때 만든다)
| 파일 | 내용 | 만드는 곳 |
|---|---|---|
| `data/scene.json` | 랙, CRAC, 통풍구, 격벽의 상자 좌표(cm), 홀 크기. 원본은 장면 USD에서 뽑은 `experiments/openfoam_baseline/layout.json` | `tools/build_data.mjs` |
| `data/sensors.json` | 센서 목록: `sensorId`, `equipment`(랙·CRAC 이름), `metric`, `unit`, `range`, `warn`, `critical`, `direction` | 같은 도구, 원본은 `sim/out/sensor_manifest.json` |
| `data/rec/<시나리오>.json` | 녹화(4.3) | 같은 도구, 원본은 `sim/out/recordings/*_l2.jsonl` |
| `data/index.json` | 시나리오 목록과 설명, 각 파일 크기 | 같은 도구 |

시나리오는 L2 녹화 4종(`normal_l2`, `cooling_failure_l2`, `fan_fault_l2`, `power_spike_l2`)이다. 화면 이름은 정상, CRAC 고장, 팬 이상, 전력 급증.

### 4.3 녹화 파일 형식 (`data/rec/*.json`)
`.jsonl` 한 줄이 샘플 하나라서 5분 녹화가 약 11 MB다. 웹용으로 **센서별 배열**로 바꿔 줄인다(목표: 시나리오당 gzip 후 1 MB 이하).

```json
{
  "version": 1,
  "scenario": "fan_fault",
  "startTs": "2026-10-15T09:00:00.000Z",
  "dt": 1,
  "n": 300,
  "values": { "H01-RK01-TEMP-IN": [19.298, 19.3, ...], "...": [...] },
  "est": {
    "H01-RK01-TEMP-IN": { "lower": [18.932, ...], "upper": [19.584, ...], "conf": [0, 0, 1, ...] }
  },
  "aggregates": { "it_power": [...], "cooling_power": [...], "facility_power": [...], "pue": [...], "energy_kwh": [...] },
  "alarms": [ { "t": 31, "sensorId": "H01-CR01-FAN-SPEED", "from": "normal", "to": "warn", "value": 14.883 } ],
  "events": [ { "t": 30, "kind": "crac_fan", "target": "crac_01", "value": 0.15 } ]
}
```
- `conf` 코드: 0=없음, 1=ok, 2=caution, 3=low, 4=fallback.
- 값은 소수 3자리로 반올림한다. 값이 없는 칸(`null`)은 "오래된 값"으로 취급한다.
- `t`는 녹화 시작에서 지난 초(정수)다.
- 시간 간격 `dt`는 1초이고 변환 도구는 간격이 일정한지 확인한다. 어긋나면 변환을 실패시킨다.

### 4.4 라이브 메시지 처리
- `snapshot`: 저장소를 그 값으로 초기화(센서별 최근 값, 알람 상태, 집계).
- `sample`: 값, 품질(`good`, `bad`, `stale`), 선택 필드 `lower`, `upper`, `confidence`.
- `alarm`: 알람 상태와 알람 목록 갱신.
- `scenario`: 상단 표시줄의 시나리오 이름과 시작·종료.
- `aggregate`: 집계 값.
- 형식이 틀린 메시지는 버리고 오류 수를 센다(화면에 보이지 않게 두되 개발자 콘솔에는 요약을 남긴다). 한 건 때문에 화면이 멈추면 안 된다.
- 끊기면 2초부터 늘려 가며(최대 10초) 다시 접속한다. 끊긴 동안은 마지막 값을 "오래된 값"(회색)으로 표시하고 상단에 "연결 끊김"을 보인다.

## 5. 기능 요구사항

각 항목에 번호(FR)와 인수 기준을 붙인다. 인수 기준은 7장의 시험에서 확인한다.

### 5.1 3D 장면
| 번호 | 요구 | 인수 기준 |
|---|---|---|
| FR-01 | `scene.json`의 상자로 홀 바닥, 랙 60기, CRAC 8기, 통풍구 30개, 격벽 패널을 그린다 | 랙 60개, CRAC 8개가 보이고 위치가 `layout.json` 좌표와 같다(오차 1 cm 이내) |
| FR-02 | 단위는 cm를 m로 바꿔 쓰고, 위 방향은 Z를 Y로 바꾼다 | 랙 앞면 방향이 `front` 값과 맞다(앞면에 눈금 선) |
| FR-03 | 카메라: 궤도 회전, 확대·축소, 이동. 프리셋 3개(위에서, 비스듬히, 처음 위치) | 마우스 드래그, 휠, 터치로 조작되고 프리셋 버튼이 동작한다 |
| FR-04 | 랙은 `InstancedMesh` 묶음(몸체, 앞면 판, 윗면 덮개, 알람 테두리, 신뢰 막대)으로 그려 값을 인스턴스 색으로 칠한다. 센서가 앞면에 있어 앞면 판을 칠하고, 위나 비스듬한 각도에서도 읽히도록 윗면 덮개도 같은 색으로 칠한다 | 랙 60기가 묶음당 그리기 호출 1회 |
| FR-05 | 격벽은 반투명으로 그려 랙이 가려지지 않게 한다 | 위에서 보면 랙 색이 보인다 |
| FR-06 | 통로 이름 표시(차가운 통로 3개, 뜨거운 통로 4개)를 토글 버튼으로 켠다 | 이름이 장면 위에 붙고 카메라를 돌려도 따라간다 |

### 5.2 센서 값 저장소와 갱신
| 번호 | 요구 | 인수 기준 |
|---|---|---|
| FR-10 | 저장소는 센서별 최신 값(`value`, `quality`, `lower`, `upper`, `confidence`, `alarm`, `ts`)과 최근 2분 이력(링 버퍼)을 가진다 | 이력 길이가 120개를 넘지 않는다 |
| FR-11 | 녹화 재생은 재생 시각이 바뀔 때 해당 시각의 값으로 저장소를 갱신한다. 시간 막대로 뒤로 가도 알람 상태와 이력이 맞게 다시 계산된다 | 재생 시각 200초로 이동한 뒤의 알람 목록이 처음부터 200초까지 재생했을 때와 같다 |
| FR-12 | 알람 상태는 녹화의 `alarms`를 재생 시각까지 적용해 구한다. 화면이 알람을 새로 판정하지 않는다 | 게이트웨이가 낸 알람과 일치한다 |
| FR-13 | 값이 범위 밖이면 `bad`(자홍), 값이 없으면 회색, 오래된 값이면 짙은 회색으로 칠한다([12](12_unreal_design.md) 5장과 같다) | 규칙별 단위 시험 |

### 5.3 색과 표시 규칙 (Unreal과 같다)
| 번호 | 요구 | 인수 기준 |
|---|---|---|
| FR-20 | 온도 색은 18도(파랑) → 초록 → 노랑 → 35도(빨강) 4점 보간이다. 범위 밖은 양 끝 색으로 자른다. 색 정지점은 파랑(0.05, 0.25, 1.0), 초록(0.05, 0.85, 0.25), 노랑(1.0, 0.85, 0.05), 빨강(1.0, 0.08, 0.05)이다 | `DCTTempGradient`와 같은 값(소수 2자리 이내) |
| FR-21 | 보는 값 전환: 입구 온도(기본), 배기 온도, 전력. 값마다 범위(`range`)로 정규화한다(입구 18~35도) | 전환하면 랙 색과 범례가 같이 바뀐다 |
| FR-22 | 알람 테두리: 주의는 노랑, 위험은 빨강 선으로 랙을 감싼다. 위험은 느리게 깜박인다(0.5 Hz, 동작 줄이기 설정이면 깜박이지 않음) | 알람 상태 랙에 테두리가 보인다 |
| FR-23 | 신뢰 막대: 입구 온도 보기에서 등급이 있는 랙 위에 작은 막대를 띄운다(바탕 막대가 전체 길이를 보여 준다). 색은 등급(ok 초록, caution 노랑, low 빨강, fallback 회색), 길이는 구간 폭이 넓을수록 짧다. 길이 비율 `1 - 폭 / 4도`를 0.15~1로 자른다(등급만 있고 구간이 없으면 0.15) | `DCTConfidence::BarFraction`과 같은 값 |
| FR-24 | 색만으로 구분하지 않는다: 등급은 막대 길이와 문자(ok, caution, low, 보정 없음)로도 보인다 | 상세 패널에 등급 문자가 항상 있다 |

### 5.4 선택과 상세 패널
| 번호 | 요구 | 인수 기준 |
|---|---|---|
| FR-30 | 랙이나 CRAC를 누르면 선택(강조 선). 같은 곳을 다시 누르거나 빈 곳을 누르면 해제. 마우스를 올리면 이름과 값을 말풍선으로 보인다 | 선택 상태가 상세 패널과 장면에 같이 보인다 |
| FR-31 | 상세 패널: 장비 이름, 소속(줄), 지표별 값과 단위, 알람 상태(문자와 색) | 랙은 입구·배기 온도와 전력, CRAC는 팬 속도·회수·급기 온도 |
| FR-32 | 입구 온도에 구간이 있으면 "값 ± 폭/2", 90% 구간 하한~상한, 등급 문자를 보인다. 없으면 "보정 정보 없음" | L2 녹화에서 구간이 보인다 |
| FR-33 | 최근 2분 추이 그래프(선택한 지표). 구간이 있으면 띠로 같이 그린다. 알람 기준선(주의, 위험)을 점선으로 그린다 | 그래프가 재생에 맞춰 움직인다 |
| FR-34 | 방향키와 Tab으로 랙을 옮겨 선택할 수 있다(줄 이동은 위아래, 같은 줄은 좌우) | 키보드만으로 모든 랙을 선택할 수 있다 |

### 5.5 알람 목록과 집계
| 번호 | 요구 | 인수 기준 |
|---|---|---|
| FR-40 | 알람 목록: 재생 시각까지 발생한 알람을 최근 순으로. 항목은 시각, 장비, 지표, 상태 변화(예: 정상 → 주의), 값 | 항목을 누르면 해당 장비가 선택되고 카메라가 부드럽게 이동한다(0.6초) |
| FR-41 | 정상으로 돌아온 알람은 목록에 남기되 흐리게 보인다 | 상태 변화 순서가 맞다 |
| FR-42 | 상단에 집계: IT 전력, 냉각 전력, PUE(소수 2자리). 값이 없으면 `–` | 녹화의 집계와 같다 |
| FR-43 | 시나리오 사건(예: "30초 CRAC_01 팬 15%")을 시간 막대 위에 표시로 보인다 | 표시에 마우스를 올리면 설명이 나온다 |

### 5.6 재생 조작 (녹화 모드)
| 번호 | 요구 | 인수 기준 |
|---|---|---|
| FR-50 | 재생과 일시정지, 속도 1배·2배·5배·10배, 시간 막대, 반복 켜기·끄기 | 동작 확인 |

## 6. 비기능 요구

### 6.1 성능과 용량
| 항목 | 기준 |
|---|---|
| 첫 화면까지(캐시 없음, 보통 노트북, 100 Mbps) | 3초 안팎, 최대 5초 |
| 첫 로딩 총 용량(gzip) | 1.5 MB 이하(화면 코드와 Three.js, `scene.json`, `sensors.json`, 정상 시나리오 녹화) |
| 시나리오 전환 | 추가 내려받기 1 MB 이하, 1초 안에 전환 |
| 프레임 | 60 FPS 목표, 30 FPS 이상(보통 노트북 내장 그래픽) |
| 메모리 | 탭 하나 300 MB 이하 |
| 라이브 | 초당 약 200건 갱신을 받아도 프레임이 떨어지지 않는다(메시지를 쌓아 한 프레임에 한 번 반영) |

### 6.2 호환성
- 최신 Chrome, Edge, Firefox, Safari(WebGL 2 지원)에서 동작한다. WebGL을 쓸 수 없으면 "이 브라우저는 WebGL을 지원하지 않는다"와 영상 링크 자리를 보인다.
- 반응형: 폭 360px까지 가로 스크롤 없이 쓸 수 있다.

### 6.3 접근성
- 색만으로 상태를 구분하지 않는다(FR-24, 알람은 문자와 테두리).
- 키보드로 선택, 재생 조작, 도움말을 쓸 수 있다.
- 시스템의 "동작 줄이기" 설정이면 깜박임과 카메라 이동 애니메이션을 끈다.
- 글자 대비는 어두운 배경에서 4.5:1 이상.

### 6.4 보안과 공개 기준
- 읽기 전용이다. 화면에서 서버로 보내는 메시지는 없다(게이트웨이도 받지 않는다).
- 정적 배포물에는 가상 시설의 결과만 들어간다. 배포 전에 금지어 점검을 거친다(`.claude/skills/clean-room-check`).
- 라이브 주소는 FR-63의 규칙만 받는다. 값은 `textContent`로만 넣고 HTML로 해석하지 않는다.
- 외부 서버로 가는 요청이 없다(글꼴, 분석 도구, CDN 모두 쓰지 않는다. 라이브러리는 빌드에 포함).
- 콘텐츠 보안 정책(CSP) 메타 태그로 같은 출처와 지정한 WebSocket만 허용한다.

### 6.5 오류 처리
| 상황 | 동작 |
|---|---|
| 녹화 파일을 못 받음 | 오류 문구와 다시 시도 버튼. 장면은 값 없이(회색) 유지 |
| 녹화 형식이 틀림(버전, 길이) | 그 시나리오를 열지 않고 이유를 보인다 |
| 라이브 메시지가 틀림 | 버리고 개수만 센다(4.4) |
| 센서 ID가 모르는 것 | 무시하고 개수만 센다 |
| 값이 `NaN`이나 문자 | 값 없음으로 취급 |

**알려진 한계와 아직 못 한 것**
- 눈으로 본 확인은 캡처(`shots/`, 저장소에는 올리지 않는다)로만 했다. 색감과 읽기 쉬움은 사용자가 직접 확인해야 한다.

- 사양 5.1 FR-06(통로 이름), FR-34(키보드 선택)는 구현했고 자동 확인했다. FR-43(시간 막대의 사건 표시)은 구현했지만 마우스를 올려 설명을 보는 동작은 자동 확인하지 못했다.
- 모델은 glb가 아니라 상자 좌표(`scene.json`, 8 KB)다. 장비 모양을 살리려면 11장의 glb 변환을 이어서 검토한다.
- 정적 배포(GitHub Pages)는 설정하지 않았다. 사용자가 켜기로 정하면 `npm run build` 결과(`dist/`)를 올린다.
- 개발 도구 의존성 취약점은 `npm audit`에서 0건이다(2026-11-02 확인, vite 6.4.5, vitest 5.0.5, three 0.170.0, puppeteer-core 25.16.0).

## 11. 열린 문제
- 건물 외관과 텍스처를 가볍게 넣을지(범위 밖으로 두었다). 시제품 측정 뒤 정한다.
- ~~glTF 모델로 바꿀지~~ **구현됨(2026-11-03)**: `blender/scripts/export_glb.py`가 `rack.blend`, `crac.blend`를 텍스처 없이 glb로 내보낸다(Blender 5.1 확인, 랙 4,436, CRAC 3,312 삼각형, gzip 각 약 39 KB). 웹은 재질별로 합쳐 인스턴스로 그리고 값 색 판을 반투명으로 겹친다. "장비 모양" 단추로 상자와 바꾼다. 아래는 결정 당시의 기록이다. glTF 모델로 바꿀지: 지금은 상자 좌표(`scene.json`)로 충분하다. 장비 모양을 살리려면 `rack.usda`, `crac.usda`를 glb로 변환하는 경로를 시제품 뒤에 검토한다(Blender 5.1 가져오기·내보내기 또는 USD 도구, 확인 날짜와 버전을 적는다).
- 열 분포를 보여 줄 방법(바닥 히트맵 등): 랙 색만으로는 통로 사이 공기 흐름을 알 수 없다. 이 화면에는 넣지 않고 Unreal 볼륨에 맡긴다.
- 정적 배포를 켤 때의 주소와 공개 시점: 사용자가 정한다.

- 직접 시뮬레이션(브라우저 간이 모델)과 로컬 계산 서버 연결은 [21 웹 직접 시뮬레이션 명세](21_web_simulation_spec.md)에서 다룬다(간이 모델은 구현됨).
- 외관 → 홀 → 시뮬레이션 흐름(외관 단계, 화면 이동 명령)은 [20 흐름 명세](20_platform_flow_spec.md)에서 정한다. 웹 쪽 요구는 FR-80번대이고 구현되었다(2026-11-02). 처음 화면이 외관으로 바뀌어서 이 문서의 "처음 화면은 홀" 설명은 `?stage=hall`을 붙였을 때의 이야기다.
