# 34. 격벽 방식: 열기 통로 격리(HAC)와 냉기 통로 격리(CAC)

- 상태: 초안 (2026-11-12). 장면, 우리 계산, OpenFOAM 사례, 웹 보기까지 했다. **기본은 HAC**이고 모든 센서 값, 녹화, 보정 모델은 HAC 기준이다.
- 목적: 데이터센터에서 흔히 쓰는 두 격벽 방식을 같은 홀에서 바꿔 보며 공기 흐름의 차이를 보여 준다(2026-11-10 사용자 요청 "CAC, HAC 두 가지 케이스 다 보여줄 수 있을지", 2026-11-12 "내부로 들어와서 CAC, HAC 방식 선택해서 하나씩 볼 수 있게").
- 관련: [33 이중 바닥](33_raised_floor_plenum.md), [ADR-009](decisions/ADR-009-hall-layout-and-cooling.md), [용어집](07_glossary_and_writing_rules.md)
- 시각화 목적이며 공학적 정확성을 주장하지 않는다.

## 1. 두 방식

| | 열기 통로 격리(HAC, Hot Aisle Containment) | 냉기 통로 격리(CAC, Cold Aisle Containment) |
|---|---|---|
| 막는 곳 | 랙 뒷면끼리 마주 보는 열기 통로(지붕 + 옆판) | 랙 앞면끼리 마주 보는 냉기 통로(지붕 + 줄 끝 문) |
| 방의 나머지 | 차갑다(찬 공기가 방에 퍼짐) | 뜨겁다(랙이 내보낸 공기가 방에 퍼짐) |
| 공조기 회수 | 막힌 열기 통로 끝에서 바로 | 방 공기에서 |
| 공급이 모자랄 때 | 열기 통로의 남는 뜨거운 공기가 지붕 틈으로 방에 샌다 | 방의 뜨거운 공기가 냉기 통로 지붕 틈으로 들어와 랙이 빨아들인다 |

## 2. 설정과 장면

- `usd/scenes/*.config.json`의 `containment.type`: `"hot"`(기본) 또는 `"cold"`. CAC 설정은 `usd/scenes/hall01_cac.config.json`(기본 설정과 `containment.type`만 다름) → 장면 `_hall01_cac.usda`(gitignore된 `_*` 규칙으로 저장소에 올리지 않는다. `build_scene.py`로 다시 만든다). 두 설정이 어긋나지 않게 기본 설정을 고치면 CAC 설정도 같이 고친다.
- CAC 장면: `Containment/ColdAisle_NN_Roof`(냉기 통로 위, 랙 줄 길이만큼, 높이 200 cm), `ColdAisle_NN_Door_W`, `_Door_E`(줄 끝 미닫이 문). 열기 통로에는 격벽이 없다.
- 조명: HAC는 열기 통로 조명을 격벽 지붕 아래에, CAC는 냉기 통로 조명을 격벽 지붕 아래(지붕 안에 들어가는 4개)에 둔다. 나머지 통로 조명은 천장에 붙는다.

## 3. 계산

| | 우리 계산(`hall60_sim.py`) | OpenFOAM(`gen_case.py`) |
|---|---|---|
| 격벽 문, 옆판 | 막힌 칸 | 막힌 칸 |
| CAC 지붕 | 통과 쉬움 `CAC_ROOF_SIGMA = 0.0005`인 칸(틈이 있는 판) | 열린 비율 2 %(`CAC_ROOF_OPEN`)인 판의 Forchheimer 저항(K ≈ 7000을 칸 두께로 나눔), 모든 방향 |
| 남는 배기 | 방으로 퍼진다(새는 길을 따로 두지 않는다) | 같음 |

두 값(0.0005, 2 %)은 **근거 없는 가상 값**이다. 지붕 틈의 크기에 따라 고장 때 들어오는 뜨거운 공기 양이 달라진다.

**우리 계산 확인 (2026-11-12, 10 cm, fv, 이중 바닥 + 장애물, 랙 10 kW)**

| 조건 | 공급 | 지붕 틈으로 들어온 양 | 열 수지 | 입구 평균 / 최고(센서 높이 1.2 m) | 공조기 회수 온도 |
|---|---|---|---|---|---|
| 정상 | 57.6 | 거의 0 | +0.03 % | 18.00 / 18.00 | |
| CRAC_02 정지 | 48.0 | 9.6 m³/s | −0.01 % | 18.03 / 18.03 | 28.4 |

- 고장 때 모자란 9.6 m³/s가 지붕 틈으로 들어오는 것은 맞게 나온다.
- 그런데 센서 높이(1.2 m)의 입구 온도는 거의 오르지 않았다. 지붕으로 들어온 뜨거운 공기가 섞이지 않고 랙 위쪽 흡입구로 바로 빨려 들어가기 때문으로 보인다(퍼텐셜 흐름은 섞임이 약하다). 공조기 회수 온도(28.4도)가 랙 배기 평균보다 높은 것도 랙 위쪽 흡입 공기가 뜨겁다는 뜻이다. **OpenFOAM과 비교해 확인해야 한다(아래 4장).**

## 5. 웹 보기

- 홀 안 표시 줄의 **격벽: HAC / CAC** 단추. CAC를 고르면 격벽, 조명(서버실 껍데기 `hall_shell_cac.glb`), 공기 흐름(`flow_cac`, 정상 상태 하나)이 바뀌고 공기 흐름을 켠다.
- CAC에서는 "값은 HAC 기준"이라고 표시한다. 온도 색, 센서 값, 녹화, 시뮬레이션 메뉴는 HAC로 계산한 값 그대로다. CAC 흐름장은 정상 상태 하나뿐이라 팬을 바꿔도 흐름은 그대로다.
- 장면 자료: `scene.json`의 `variants.cac`(판 목록, 껍데기, 흐름 파일 이름). 원본은 `experiments/openfoam_baseline/layout_cac.json`(`export_layout.py ../../usd/scenes/_hall01_cac.usda layout_cac.json`).

## 6. 다음 단계와 다른 방법

- CAC를 센서 값까지 넣으려면(모니터링, 시뮬레이션 메뉴): 보정 모델 학습 데이터(OpenFOAM 68개)를 CAC 장면으로 한 벌 더 만들어야 한다(약 20시간). 지금은 보기만 한다.
- 다른 방법: 웹에서 CAC 격벽만 그리고 흐름은 HAC 것을 그대로 쓰기 — 공기 흐름이 격벽을 뚫고 지나가 보여 쓰지 않았다.
